# Noorish

A calm Quran reader with word-by-word meanings, tafsir, recitation, and personal notes and bookmarks, growing into a quiet companion for everyday Muslim life.

## The name

**Noorish** blends _noor_ (نور, "light", as in _Allahu nurus-samawati wal-ard_, An-Nur 24:35) with the English word _nourish_. Read either way, it says what the app is for: daily light that nourishes the soul. The name deliberately isn't tied to one feature, so it still fits as prayer, dhikr, and other features join the Quran reader.

Say it like "nourish": **NOOR-ish**.

## Tech Stack

- **Framework:** [TanStack Start](https://tanstack.com/start) (React 19, TanStack Router, server functions) on Vite + Nitro
- **Data:** TanStack Query, Drizzle ORM, PostgreSQL
- **Auth:** Better Auth (email + password)
- **Tooling:** Bun, Biome, `tsgo`, Vitest
- **Hosting:** Vercel

## Prerequisites

- Node.js 24+ and Bun 1.3+ (see `engines` / `packageManager` in `package.json`)
- A [Supabase](https://supabase.com) project for development (Postgres 18+, since the schema uses `uuidv7()`)

## Quick Start

```bash
bun install
cp .env.example .env.local   # then set DATABASE_URL to your Supabase dev project
bun db:migrate
bun db:seed
bun dev                      # http://localhost:3000
```

Sign in with `test@example.com` / `password123` (created by the seed).

## Roadmap

Ideas for where Noorish goes next. The rule for every one of them: **the reader stays the heart of the app, and nothing new gets louder than it.**

### Design principles for new features

- **One calm home.** New features live behind the existing dock and sheets, not in new toolbars. The dock already holds five slots, so rather than adding more, group daily features into a single **Today** sheet (prayer times, the day's verse, adhkar) that opens like the others.
- **Opt-in, not pushed.** No badges, streak guilt, or red dots. Anything that notifies is off until the reader turns it on.
- **Same visual language.** Reuse the monochrome tokens, gold accents, and ornament components; a feature that needs a new color or layout pattern is a sign it is too loud.
- **Hideable.** Each feature can be switched off in Settings, so someone who only wants to read never sees the rest.
- **One folder per feature.** Each lands as `src/features/<feature>/`, like the existing ones (see `CLAUDE.md`).

## Deploying to Vercel

1. Import the repo in Vercel; `vercel.json` sets the TanStack Start framework preset and Bun install.
2. Create a production Supabase project (Postgres 18+, since the schema uses `uuidv7()`). In its settings, turn off the Data API: the app talks to Postgres directly, and leaving the API on would expose the `public` tables (users, sessions, accounts) over REST.
3. Set environment variables:
   - `DATABASE_URL` — Supabase **transaction pooler** URL (port 6543). The direct `db.<ref>.supabase.co` host is IPv6-only, and Vercel can't reach it
   - `BETTER_AUTH_SECRET` — 32+ random chars (`openssl rand -hex 32`)
   - `BETTER_AUTH_URL` — production origin, e.g. `https://noorish.vercel.app` (optional; inferred per request when unset, which keeps preview deployments working)
4. Run migrations against the production database before (or right after) deploying:

   ```bash
    DATABASE_URL=<production session-pooler url> bun db:migrate
   ```

   Migrations are deliberately not run in the Vercel build, so preview builds can't change the production schema.
